Test phase evidence: the CI wiring, parsed and executed
=======================================================

The workflow files are parsed into a job model with the same YAML parser
Actions uses, rather than grepped, and then the new job's own run steps are
executed locally. `npm ci` is skipped because node_modules here is already
installed from the same lockfile.


ci.yml: jobs and their order
  - check
      uses: actions/checkout@v5
      uses: actions/setup-node@v5  [node 24]
      run: npm ci
      run: npm run check
      run: npm audit --omit=dev --omit=peer --audit-level=high
      run: npm run pack:check
  - no-pi-install  (needs: check)
      uses: actions/checkout@v5
      uses: actions/setup-node@v5  [node 24]
      run: npm ci
      run: npm run no-pi-install:check

release.yml: jobs and their order
  - release
      uses: actions/checkout@v5
      uses: actions/setup-node@v5  [node 24]
      run: npm install -g npm@latest
      run: tag_version="${GITHUB_REF_NAME#v}"
pkg_version="$(node -p "require('./package.json').version")"

What the parsed model says about the new job:
  ci.yml no-pi-install waits on: check
  ci.yml check runs: npm ci | npm run check | npm audit --omit=dev --omit=peer --audit-level=high | npm run pack:check
  package.json check = npm run typecheck && npm run imports:check && biome check . && npm run test
  release.yml release order: npm install -g npm@latest -> tag_version="${GITHUB_REF_NAME#v}"
