Test phase evidence: driving the installed, Pi-free bin by hand
===============================================================

This is a manual end-to-end reproduction of what a user gets from
`npx pi-worklist`, run independently of scripts/no-pi-install-check.ts so the
raw command surface is visible rather than the check script's step lines.

It packs the real publishable tarball, installs it into a scratch directory
with --omit=dev --omit=peer, shows that no @earendil-works package and no
typebox exist anywhere in the installed tree, then drives
node_modules/.bin/pi-worklist (the shipped bin shim) across list, add, show,
find, next, ready, waves, apply-plan --dry-run, a refused mutation, the same
mutation with --confirm, a typed NOT_FOUND failure, and the terminal board.

worklist.json is hashed before and after the dry run and after the refused
mutation to show both left it byte-identical.

==============================================================
 1. Pack the publishable tarball (prepack build runs)
==============================================================

$ npm pack --pack-destination /tmp/no-pi-evidence/run-vn9y3u/pack

> pi-worklist@0.17.0 prepack
> npm run build


> pi-worklist@0.17.0 build
> node -e "fs.rmSync('dist',{recursive:true,force:true})" && tsc -p tsconfig.build.json

pi-worklist-0.17.0.tgz
(exit 0)
