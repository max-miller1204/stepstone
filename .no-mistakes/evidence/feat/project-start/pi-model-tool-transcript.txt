=== 1. The model-facing tool advertises start, branch, and clear ===
action enum: ["list","add","apply-plan","move","start","update","set_status","delete","complete","reopen","archive","set_active"]
action description: Action to perform. 'apply-plan' validates or atomically adds a project plan. 'move' reorders a Session Task in its queue or a Project Goal in the roadmap. 'start' claims or releases a Project Goal branch. 'complete', 'reopen', 'archive', and 'delete' on project goals require confirm=true.
branch: {"type":"string","description":"Branch claiming a Project Goal for project start. Omit only when clear=true."}
clear: {"type":"boolean","description":"For project start, remove the existing branch claim instead of setting one."}

=== 2. Claim a Project Goal for a branch; its status is left alone ===
> worklist {"scope":"project","action":"add","title":"Dispatch me"}
< Added project goal dispatch-me: Dispatch me
  details.goal: {"id":"dispatch-me","title":"Dispatch me","status":"open","createdAt":"2026-08-12T07:03:38.490Z","updatedAt":"2026-08-12T07:03:38.490Z"}

> worklist {"scope":"project","action":"start","id":"dispatch-me","branch":"feat/pi-dispatch"}
< Started project goal dispatch-me on feat/pi-dispatch
  details.goal: {"id":"dispatch-me","title":"Dispatch me","status":"open","createdAt":"2026-08-12T07:03:38.490Z","updatedAt":"2026-08-12T07:03:38.498Z","branch":"feat/pi-dispatch"}

=== 3. What the model reads back afterwards ===
> worklist {"scope":"project","action":"list"}
< [open] dispatch-me: Dispatch me

=== 4. start needs exactly one of branch or clear ===
> worklist {"scope":"project","action":"start","id":"dispatch-me"}
< the call failed: branch is required for project start unless clear is true.

> worklist {"scope":"project","action":"start","id":"dispatch-me","branch":"feat/other","clear":true}
< the call failed: Project start cannot combine branch with clear.

=== 5. Optimistic concurrency guards the claim ===
> worklist {"scope":"project","action":"start","id":"dispatch-me","branch":"feat/stolen","expectedUpdatedAt":"2020-01-01T00:00:00.000Z"}
< the call failed: Project goal dispatch-me changed from 2020-01-01T00:00:00.000Z to 2026-08-12T07:03:38.498Z.

=== 6. Release it again, and the model is told so in words ===
> worklist {"scope":"project","action":"start","id":"dispatch-me","clear":true}
< Released project goal dispatch-me
  details.goal: {"id":"dispatch-me","title":"Dispatch me","status":"open","createdAt":"2026-08-12T07:03:38.490Z","updatedAt":"2026-08-12T07:03:38.501Z"}

=== 7. branch and clear are Project Goal fields; a Session Task call is refused ===
> worklist {"scope":"session","action":"add","title":"Session chunk","branch":"feat/pi-dispatch"}
< the call failed: branch is only supported for project goals.

> worklist {"scope":"session","action":"add","title":"Session chunk","clear":true}
< the call failed: clear is only supported for project goals.

=== 8. Completing a claimed goal releases the claim ===
> worklist {"scope":"project","action":"start","id":"dispatch-me","branch":"feat/pi-dispatch"}
< Started project goal dispatch-me on feat/pi-dispatch
  details.goal: {"id":"dispatch-me","title":"Dispatch me","status":"open","createdAt":"2026-08-12T07:03:38.490Z","updatedAt":"2026-08-12T07:03:38.505Z","branch":"feat/pi-dispatch"}

> worklist {"scope":"project","action":"complete","id":"dispatch-me","confirm":true}
< Project goal dispatch-me is now done
  details.goal: {"id":"dispatch-me","title":"Dispatch me","status":"done","createdAt":"2026-08-12T07:03:38.490Z","updatedAt":"2026-08-12T07:03:38.507Z","completedAt":"2026-08-12T07:03:38.507Z"}

=== 9. A finished goal cannot be claimed again without reopening it ===
> worklist {"scope":"project","action":"start","id":"dispatch-me","branch":"feat/again"}
< the call failed: A done or archived Project Goal must be reopened with confirm=true before activation.
